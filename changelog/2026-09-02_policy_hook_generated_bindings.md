# Policy hook Go bindings generated from the published contract

## Executive Summary

- The policy hook's request and response types and its HTTP client are now generated from
  `verifier/policy_hook_openapi_v1.yaml` instead of hand-written alongside it. The spec is the
  single definition, so the Go types cannot drift from what an operator builds against.
- No wire change. The bytes on the wire, the URL, the headers, and the PASS/FAIL/retry semantics
  are all identical to the previous release. The published spec is untouched, so the generated
  operator documentation is unchanged too.
- `TestOpenAPISpecMatchesContract` is gone. It existed to catch drift between two hand-maintained
  definitions, and that drift is now a compile error.

## What changed

`verifier/pkg/policy/internal/policyapi` is generated by `oapi-codegen` v2.5.1 from the published
spec, configured by `verifier/policy-codegen.yaml`. `verifier/openapi.go` carries the
`//go:generate`, next to the docs generator added earlier. Both are covered by the existing
repo-hygiene job, which runs `check_repo_clean.sh ... generate` and fails if regeneration changes
the tree, so neither the bindings nor the docs can go stale.

### The overlay, and why the spec has no Go in it

`verifier/policy-overlay.yaml` maps the contract's counters onto the unsigned Go types the verifier
already uses: `uint64` for the block numbers and the sequence number, `uint32` for the gas limits
and the finality word, `uint8` for the two version fields. Without it, `format: int64` generates
Go `int64` and every assignment needs a conversion.

The overlay is a separate file rather than `x-go-type` inline in the spec because the spec is
published. An operator reading the contract should not be reading our language bindings. This
follows `indexer/overlay.yaml`; `chainlink-canton` needs no overlay at all because its EDS specs
never use `format: int64`, which is the cleaner end state and where the remaining integer fields
here could go later.

Chain selectors are absent from the overlay. They are decimal strings in the contract, so they need
no mapping, which is the payoff from the previous release's decision.

### Types

The generated types are aliased in `contract.go` under the names the package already used
(`EvaluateRequest`, `EvaluateResponse`, `MessageV1`, `TokenTransferV1`, `Decision`,
`DecisionPass`/`Fail`/`Hold`, `SchemaVersion`), so `verifier/pkg/policy`'s public surface is
unchanged. Two shapes did change, both inside those types:

- Field names follow the generator: `MessageID` is `MessageId`, `VerifierID` is `VerifierId`,
  `CCIPReceiveGasLimit` is `CcipReceiveGasLimit`, `CCVAndExecutorHash` is `CcvAndExecutorHash`.
- The contract's optional response fields are pointers: `EvaluateResponse.MessageId` and
  `.Reason` are `*string`. That is an improvement rather than a cost, because an endpoint that
  omits `message_id` is now distinguishable from one that sends it blank, and only the former
  should skip the echo check.

No caller outside the package touches either. The only external use of these types is the
`Checker` interface and a test double in `verifier/pkg/commit`, neither of which reads a field.

### Client

`HTTPChecker` uses the generated client for request construction: resolving `base_url` against the
contract's operation path, and setting the content type. HMAC signing is a `RequestEditorFn` over
the exact marshaled bytes, which is what the signature covers.

It deliberately does not use the generated `ClientWithResponses` helpers. Those read the response
body with no limit and fold every status into one shape, and the 64 KiB bounded read and the
unavailable-versus-rejected split are the reason this package exists rather than reusing a shared
HTTP client. The low-level generated method returns `*http.Response`, so the request is generated
and the response handling stays explicit.

## Testing

- `TestHTTPChecker_PostsTheDerivedEvaluateURL` is new and covers the one thing generation does not
  tie together: the generated client resolves the operation path itself, while
  `Config.EvaluateURL` derives the same URL for logs, errors, and the validation that rejects a
  `base_url` already ending in the operation path. It asserts they agree for a bare host, a
  trailing slash, and a gateway path prefix.
- `TestOpenAPISpecDeclaresEvaluateOperation` now asserts the spec's operation path equals
  `policy.EvaluatePath`. Moving the path in the spec would otherwise leave the client posting the
  new path while the logs and validation named the old one.
- `TestOpenAPISpecEnums` is replaced by `TestReservedHoldIsRefused`. Asserting the spec's enum
  matches the Go constants is circular once the constants are generated from it; that HOLD is
  still refused at runtime is not.
- `TestPublishedMessageCoversProtocolMessage` is unchanged and matters more than before. It is now
  the only thing tying the published shape to `protocol.Message`, which is not generated.
